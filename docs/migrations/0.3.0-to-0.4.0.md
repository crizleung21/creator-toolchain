# Creator State Migration — 0.3.0 to 0.4.0

## Status

Transactional migration and explicit rollback are supported in Creator Toolchain `v1.1.0`.

## Dry-Run Plan

```bash
python3 scripts/migrate_creator_state.py \
  --root . \
  --timestamp 2026-07-17T16:47:46Z \
  --plan /tmp/creator-state-migration-plan.json
```

Dry-run records source/target SHA-256 values and changed fields for all ten state surfaces without writing state.

## Transactional Write

```bash
python3 scripts/migrate_creator_state.py \
  --root . \
  --write \
  --backup /tmp/creator-state-0.3.0-backup
```

The backup destination must not already exist. Migration reads all ten source files, validates `0.3.0`, transforms in memory, validates the complete `0.4.0` target, records original checksums and modes, atomically replaces each surface, and restores every original byte if any operation fails.

## Explicit Rollback

```bash
python3 scripts/migrate_creator_state.py \
  --root . \
  --rollback /tmp/creator-state-0.3.0-backup
```

Rollback validates the backup manifest, restores each file, and verifies byte equivalence.

## Schema Changes

- all surfaces use `schema_version: 0.4.0`;
- all surfaces declare ISO-8601 creation and update timestamps;
- `surfaces.json` contains the materialized canonical registry;
- rule domains declare scope, owner, priority, and update timestamp;
- Health records evidence and calculation time;
- decisions, rules, commands, preferences, and existing records are preserved.
