# Creator State Migration — 0.3.0 to 0.4.0

## Status

Transactional migration and explicit rollback are enabled. The Creator Toolchain repository state was migrated on the Phase 1 branch using timestamp `2026-07-17T16:47:46Z` and validated against the formal `0.4.0` schemas and cross-file contract.

## Dry-Run Plan

```bash
python3 scripts/migrate_creator_state.py \
  --root . \
  --timestamp 2026-07-17T16:47:46Z \
  --plan /tmp/creator-state-migration-plan.json
```

The plan records source and target SHA-256 values and changed top-level fields for all ten state surfaces. Dry-run performs no state writes.

## Transactional Write

```bash
python3 scripts/migrate_creator_state.py \
  --root . \
  --write \
  --backup /tmp/creator-state-0.3.0-backup
```

`--write` requires a non-existent backup destination. The migration:

1. reads all ten source files;
2. rejects non-`0.3.0` input;
3. transforms all files in memory;
4. validates the complete target workspace before writing;
5. writes a backup manifest with original SHA-256 and file mode;
6. atomically replaces each surface;
7. runs post-write schema and cross-file validation;
8. automatically restores the backup if any operation fails.

## Explicit Rollback

```bash
python3 scripts/migrate_creator_state.py \
  --root . \
  --rollback /tmp/creator-state-0.3.0-backup
```

Rollback validates every backup checksum before writing and verifies that every restored state file is byte-equivalent to its pre-migration source.

## Schema Changes

- all surfaces now use `schema_version: 0.4.0`;
- all surfaces declare ISO-8601 `created_at` and `updated_at`;
- `surfaces.json` now carries the full canonical registry contract;
- rule domains declare `scope`, `owner`, and `updated_at`;
- `state.json` health metadata records the migration validation;
- existing decisions, rules, commands, preferences, and records are preserved.
